## 晚间：Worker 加载链路最小验证

### 技术评估结论
- 音乐理解 Worker 不能复用和弦分析的 ES6 Module Worker 模式
- 必须使用经典 Worker + `importScripts()` 方式（TF.js 的动态后端选择要求、essentia.js-model 设计假设）
- 两个 Worker 完全独立，不共享 Essentia WASM 实例

### 关键发现
- `essentia-wasm.umd.js` 在 Worker 中以 `var Module` 暴露（非 `self.EssentiaWASM`）
- `essentia.js-model.umd.js` 的 UMD wrapper 会设置 `self.EssentiaModel = {}`
- require `Module({ locateFile })` 来定位 .wasm 文件路径

### 验证环境搭建
- 安装 `@tensorflow/tfjs@4.22.0`
- `scripts/copy-essentia.js` 新增 `essentia-wasm.umd.js` + `essentia.js-model.umd.js` 复制
- `public/libs/tf.min.js` (1.4MB) 从 `node_modules/@tensorflow/tfjs/dist/` 复制
- `public/inference.worker.js` — 经典 Worker，5 步验证
- `src/pages/music-insight/index.tsx` — 验证页面（Ant Design Card + 按钮）
- dev server 启动在 http://localhost:8000/music-insight

### 待验证
- ✅ 全部 9 项通过：EssentiaWASM 加载、EssentiaTFInputExtractor/TensorflowMusiCNN/TensorflowVGGish/EssentiaTensorflowJSModel 类可用、Extractor 创建成功、computeFrameWise 执行成功（440Hz 正弦波测试）、TF.js WebGL 后端就绪

### 最终技术方案
- **Worker 类型**：ES6 Module Worker（与 chord analysis 同款）
- **加载方式**：ES6 import essentia-wasm + essentia.js-model + @tensorflow/tfjs
- **关键坑位**：
  1. `importScripts` + essentia-wasm.umd.js → `exports` 未定义（无解）
  2. `EssentiaTFInputExtractor` 传参必须是原始 Emscripten 模块（`EssentiaWASM`），不是 `Essentia` 实例
  3. 经典 Worker 方案完全不可行，ES6 Module Worker 是唯一路径
