> 基于《试听下载技术方案.md》与《Suno试听缓存-PRD.md》定稿生成

## 2. Rust 依赖选型（解密）

| 用途             | crate                 | 版本建议                      | 说明                                                                    |
| ---------------- | --------------------- | ----------------------------- | ----------------------------------------------------------------------- |
| SHA-256(glt)     | `sha2`                | 已有(0.10)                    | GCM 解包密钥，无需新增                                                  |
| AES-256-GCM 解包 | `aes-gcm`             | 0.10                          | 解出 32B ctrKey / 16B ctrIv；`aad=utf8(content_id)`，iv=key[0:12]       |
| AES-CTR 解本体   | `aes` + `ctr`         | 0.8 / 0.9                     | `Ctr128BE<Aes256>`，counter 全 128 位递增，与 WebCrypto length=128 一致 |
| 调用 ffmpeg      | `tokio`               | 1.x（`features=["process"]`） | `spawn_blocking` 亦可，避免阻塞异步命令                                 |
| 进度回调         | `tauri::command` 事件 | 内置                          | 逐块下载/解密进度推送前端                                               |

> 说明：全部采用 RustCrypto，无 OpenSSL 系统依赖，Cargo 锁定版本，构建可在本项目现有 Tauri 环境内完成。

## 4. 里程碑与任务分解

### M1 · 网络层（`suno_probe.rs`）

1. 链接归一化：`/s/<token>`、`/song/<uuid>` 校验提取 uuid。
2. 请求头工厂：`browser-token`（前端复刻逻辑本地生成）、`device-id`（随机 UUID）、`origin/referer: https://suno.com/`、UA。
3. `share/code/{token}`：取 `content_id`。离线短链校验失败 → 明确报错。
4. `mango/rights`：`{content_id, content_type:"clip"}` → `{key,iv,glt}`（wrapped）。
5. CDN 下载：`https://d2lwuy8qc234o3.cloudfront.net/1/clip/<uuid>.m4a`（注意域名 `...o3` 非 `...3o`），分块下载 + 超时/重试 + 进度事件。
6. 元数据（标题/封面选填）：在实现时通过 `share/code` 响应字段 / 页面 OG 标签探明来源；缺失不阻塞（仅影响文件名/标签），作为返回的调试信息。

- **验收**：给定样本链接返回加密 m4a + rights；错误分类（无效链接/私密/超时/风控）清晰。

### M2 · 解密 + 转码

1. `suno_decrypt.rs`：按技术方案 §0.1 算法实现 AES-GCM 解包 + AES-CTR 逐块解密，输出以 `ftyp`+`moov` 开头的 fMP4。
2. 缓存目录：落 `appData` 下固定子目录，按 `content_id` 命名。
3. `suno_transcode.rs`：探测 PATH；未命中用 `imageio-ffmpeg` 托管二进制（后端管理）。
4. ffmpeg 命令：`ffmpeg -i <fmp4> -loglevel error -codec:a libmp3lame -b:a 320k -map_metadata 0 -f mp3 <out.mp3>`；写入 `-metadata title=/artist=`（取自元数据，选填）。
5. 输出校验：时长、大小、`ffprobe` 码率 ≈320k、采样率/声道合法。

- **验收**：样本链接 → 320kbps mp3 可在本机播放；错误/格式异常有明确阶段提示。

### M3 · 前端集成（`suno-trial-cache` 页面）

1. 复用 Pro 表单：链接输入、格式校验（`/song` 正则 + 短链交后端）。
2. 进度条：解析 → 抓流 → 解密 → 转码 分步状态，失败定位到阶段。
3. 结果卡：封面/标题/时长/大小；操作=保存 mp3 / 试听（`Audio` 播放）/ 复制标题 / 重新缓存 / 删除。
4. 缓存列表：复用 `db.ts` 记录与展示，去重同 `content_id`，改名必填校验。
5. 命名口径：文案统一"缓存"，按钮"开始缓存"，不做"下载"字样。

- **验收**：全流程可从界面完成；交互无卡死；失败可取消重试。

### M4 · 灰度与回归

1. 解密单元测试：用固定样本断言输出前 40 字节 == `00 00 00 1c 66 74 79 70...`。
2. 转码单测：ffmpeg 参数 + 输出码率断言（mock/真实 ffmpeg）。
3. Tauri 集成测试（可选套件）：公开短链 → mp3 端到端（需真实网络）。
4. 现有 jest/playwright 回归；`.husky/lint-staged` 门禁（`pnpm lint`）。

- **验收**：`pnpm lint` 通过、单测通过、端到端冒烟通过。

## 5. 分支 / 发布策略

- 全部开发在 `develop`；提交用 Conventional Commit（`feat(suno-trial): ...`，触发 `git-commit` skill）。
- main 只合并经过测试的稳定版本。
- 发布：`pnpm deploy`（build + gh-pages）在 main 上执行；桌面功能以 Tauri 壳为载体。
- 遵循：单终端、单本地开发服务器；启动前先停已运行服务器。

## 6. 验证命令

- 静态：`pnpm lint`
- 单测：`pnpm jest`（新增用例）
- 前端：`pnpm dev`（max dev --port 8000）
- 端到端：Tauri 桌面壳手动冒烟（真实链接）

## 7. 风险与回滚

- Suno 前端升级改算法/密钥 → 收敛到 `suno_decrypt.rs` 单点回归。
- CloudFront 域名变动 / rights 接口调整 → 收敛到 `suno_probe.rs` 网络层，接口层错误分类。
- ffmpeg 缺失/版本行为漂移 → PATH 探测 + imageio 兜底 + 锁定参数。
- 每次里程碑在本机验证通过后再推进下一里程碑；任一环节失效不阻塞前端展示（给出明确阶段错误）。

## 8. 建议执行顺序

M1 → M2 → M3 → M4，逐步本地验证。每次里程碑独立可测、可提交。
