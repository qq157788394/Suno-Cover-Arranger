# 试听版本下载功能 · 技术方案与可行性调研

> 文档状态：已定稿（PoC 网络侧验证通过后更新） · 待评审
> 目标分支：`develop`
> 功能命名：**Suno 试听缓存**（产品口径定位为"缓存"，用于客户试听选型，规避合规风险）
> 已定决策：方案选型 **B**（Tauri Rust `reqwest`）；解密放 **Rust**；转码承载走 **ffmpeg**；输出 **320kbps mp3**；**不依赖登录态**（仅用公开接口）。
> 关联背景：Suno 更新了歌曲下载规则，普通/正式下载受限且有额度，超出后购买费用高昂，难以满足“多版本生成 → 客户选型 → 仅对选中版本正式下载”的服务模式。本功能通过解析 Suno 播放页并抓取**在线播放的加密音频流**进行本地解密，得到可试听的 m4a 文件，绕开官方正式下载，从而节省月度下载额度。

### 0. PoC 实测结论（2026-09-06，真实 Chrome 验证）

针对分享链接 `ripkWueqMkrAOnbR` 实测，**均不依赖登录态**：

| 环节     | 接口 / 行为                                                             | 实测结果                                                                                  |
| -------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 短链解析 | `GET studio-api-prod.suno.com/api/share/code/{token}`                   | 200，返回 `content_id`（歌曲 UUID）+ 分享者信息；需 `browser-token`/`device-id`/origin 头 |
| 元数据   | `POST /api/unified/feed`（`{feed_id, target_user_id}`）                 | 返回 `media_urls`，含加密播放流地址（_仅备查：最终方案不依赖 feed，见 §0.1_）             |
| 播放流   | `media_urls[].url` → `…d2lwuy8qc2343o.cloudfront.net/1/clip/<uuid>.m4a` | CloudFront 分发 `m4a-opus`，`stream:true`                                                 |
| 加密确认 | 浏览器 `<audio>` 直接加载该 m4a                                         | `MEDIA_ELEMENT_ERROR: Format error`，确认为**加密容器**，需 Suno 前端解密算法             |

注意：旧版社区接口 `studio-api.suno.ai` 已 "Service Suspended"，本项目统一改用 `studio-api-prod.suno.com`。

### 0.1 PoC 第二步 · 解密算法已端到端验证（2026-09-06，真实 Chrome + WebCrypto）

在真实播放这首歌曲时，从 Suno 前端 JS chunk（`3p2o02udgkq6r.js` / 模块 382403、913328）提取并验证了完整解密链路。**关键点：Suno 会在播放时向公开授权接口获取一把"包裹态 (wrapped)"密钥，再用 AES-GCM 解包得到真正可用的 AES-CTR 密钥，最后对整个 m4a 做 AES-CTR 解密**。全程使用浏览器标准 `crypto.subtle`（AES-GCM / AES-CTR），**可完全用 Rust（openssl 或 ring）复刻，无需逆向任何自研算法**。

完整解密算法（匿名播放路径，无需登录，仅需可本地生成的 `browser-token` + `device-id`）：

| 步骤 | 操作                                                                                                                                                                   | 关键产物                                                                                                |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 1    | `POST /api/mango/rights`，body `{"content_params":{"content_id":"<uuid>","content_type":"clip"}}`，带 `browser-token`、`device-id`、`origin/referer:https://suno.com/` | 返回 `{ key, iv, glt }`（key/iv 为 44 字节 **wrapped**；glt 为 guest license token，cookie `suno_glt`） |
| 2    | `aesKey = SHA256(glt)`，作为 AES-GCM 密钥                                                                                                                              | GCM 解包密钥                                                                                            |
| 3    | `ctrKey = AES-GCM.decrypt(iv=key[0:12], aad=utf8(contentId), key=aesKey, data=key[12:])`                                                                               | **AES-CTR 密钥**（32 字节）                                                                             |
| 4    | `ctrIv  = AES-GCM.decrypt(iv=iv[0:12],  aad=utf8(contentId), key=aesKey, data=iv[12:])`                                                                                | **AES-CTR 计数器初值**（16 字节）                                                                       |
| 5    | 下载 `https://d2lwuy8qc234o3.cloudfront.net/1/clip/<uuid>.m4a`（注意域名是 `d2lwuy8qc234o3`，非 `d2lwuy8qc2343o`）                                                     | 加密 m4a（约 4.6 MB）                                                                                   |
| 6    | `AES-CTR.decrypt(counter=ctrIv, length=128)` 逐 16 字节块解密整个 m4a                                                                                                  | 合法 fMP4                                                                                               |
| 7    | 校验输出：以 `ftyp` + `moov` 起始（实测 `66 74 79 70 69 73 6f 6d … 6d 6f 6f 76`），为 Opus-in-MP4                                                                      | 可直接被浏览器/解码器播放                                                                               |
| 8    | （后续）调用 **ffmpeg** 将 fMP4 转码为 320kbps mp3（`-codec:a libmp3lame -b:a 320k`，见 §2.6）                                                                         | 试听缓存交付物                                                                                          |

实测：解密输出的前 40 字节为 `00 00 00 1c 66 74 79 70 69 73 6f 6d 00 00 02 00 69 73 6f 6d 69 73 6f 32 6d 70 34 31 00 00 dd 0c 6d 6f 6f 76 …` —— **标准 `isom`/`iso2`/`mp41` FP4 文件头 + `moov` box**，证明加密 m4a 被正确解密。PoC 第二步完全通过。

## 1. 需求拆解

### 1.1 核心用户流程

1. 用户在 Suno 上生成多个版本的歌曲（`/s/<token>` 分享链接，例如 `https://suno.com/s/ripkWueqMkrAOnbR`）。
2. 客户需要在全部版本中试听并挑选。
3. 用户需要把**每个版本的试听音频**下载到本地 / 交给客户。
4. 客户一旦选型，用户才对**唯一的选中版本**走 Suno 官方正式下载（不占用额外额度之外的资源）。

### 1.2 功能目标

| 目标 | 说明                                                      |
| ---- | --------------------------------------------------------- |
| 输入 | 一个 Suno 分享链接（短链 `/s/xxx` 或全链 `/song/<uuid>`） |
| 解析 | 从链接解析出歌曲唯一 ID 与元数据（标题、封面、时长等）    |
| 抓取 | 获取该歌曲的**在线播放音频流**（非官方正式下载）          |
| 解密 | 将加密的 m4a 播放流通过复刻自 Suno 前端 JS 的算法解密     |
| 产出 | 可播放、可转发的 m4a（试听用途）                          |
| 边界 | 不调用任何 Suno 官方“正式下载”接口，不占用下载额度        |

### 1.3 明确不做

- 不做批量/整库下载（属于明显滥用，风险高）。
- 不做用于商业转售的去 DRM 工程；仅服务“给客户试听选型”，产出在方案中明确标注试听用途。
- 不绕过登录态去拉取未公开/私有曲目的播放流（技术可行但触犯边界）。

## 2. 可行性调研

### 2.1 Suno 播放资源机制（初查结论）

Suno 歌曲的元数据与播放资源，社区已多方逆向，关键字段为：

| 字段               | 含义                                                       | 是否计入下载额度             |
| ------------------ | ---------------------------------------------------------- | ---------------------------- |
| `audio_url`        | CDN 上可直接下载的 `mp3` 地址（如 `cdn1.suno.ai/xxx.mp3`） | **是**（这就是“官方下载”）   |
| `video_url`        | CDN 上视频版地址                                           | 是                           |
| `stream_audio_url` | **在线播放用的音频流（m4a）**                              | **否**（播放流，本方案目标） |
| `image_url`        | 封面                                                       | 否                           |

公开的模拟 API（如部分第三方服务）的返回结构中也确实包含 `stream_audio_url` / `source_stream_audio_url` 字段，证实“播放流”与“正式下载”是**两条独立通道**：播放流用于网页在线试听，官方下载则落到 `cdn*.suno.ai` 的定稿 mp3。

### 2.2 加密播放流与解密

调研确认：Suno 的**在线播放流是一个加密 m4a**，浏览器网页端会先拿到该流，再通过**内嵌在前端 JS 分片（chunk）中的私有解密函数**解码后交给播放器。

- 解密函数与密钥/算法逻辑**随 Suno 前端构建分片下发**，即任何浏览器都携带该算法。
- **用户已在本机独立验证**：抓取该 m4a 后可在本地完成解密，得到可播放的 m4a。
- 结论：解密在工程上**可复现、可本地化**，无需逆向破解密钥（密钥就藏在公开交付的前端代码中），只是需要把这段 JS 逻辑原样移植到本项目的运行环境（Rust / Python）。

> 说明：本方案不粘贴 Suno 前端私有算法的具体实现源码，只在 PoC 阶段把用户已验证的解密逻辑按最小必要范围落地到本项目，并持续跟进 Suno 前端更新（算法或密钥变更时需同步）。

### 2.3 元数据获取方式（分享链接 → 歌曲）

存在两条链路，均需在 PoC 阶段确认：

1. **公开页面/接口**：访问分享链接对应的歌曲接口，返回含 `stream_audio_url` 的元数据（部分第三方模拟器据此在不登录前提下即可解析短链）。
2. **需登录态**：Suno 近期的反爬更新（社区记载 2026-05 起增加了 `browser-token` / `device-id` 等请求头与风控）可能让*非登录*匿名请求更容易被拦截。

**结论（已确认）**：本功能只处理**公开分享链接**。公开分享即代表该曲目可公开播放；能播放即能通过本项目录的公开接口抓取加密流并解析，**不依赖登录态、无需会话凭据**。私有/未公开曲目不在需求内（无分享链接即不走本功能路径）。

### 2.4 网络可达性（本项目运行的硬约束）

本项目运行形态：

- **Web 端**：`umi@4` SPA 构建后部署到 **gh-pages（GitHub Pages 纯静态）**，无后端，浏览器直接请求 `suno.com` / `*.suno.ai` 会被浏览器 **CORS** 拦截，也无法隐藏 `browser-token`/`device-id`。
  → **纯 Web 实现不可行**。
- **Tauri 桌面壳**：`src-tauri` 的 Rust 端已使用 `reqwest`（`Cargo.toml` 已启用 `multipart`、`stream` 特性），并在 `engine_update.rs`、`main.rs` 中实测可用作**绕过 CORS 的本机代理**（现有“和弦分析”音频转发即走此路）。
  → **Tauri 端（Rust reqwest）是实现网络抓取+下载的本方案推荐落点**。

### 2.5 方案选型

| 方案                                             | 网络请求                   | 解密能力     | 结论                      |
| ------------------------------------------------ | -------------------------- | ------------ | ------------------------- |
| A. 纯 Web 前端 fetch                             | CORS 阻断                  | 浏览器内可行 | ❌ 不可行                 |
| B. Tauri Rust reqwest + 交换为明文音频后交给前端 | Rust 绕过 CORS ✅          | Rust 内实现  | ✅ 推荐                   |
| C. 本地 Python 引擎（复用 local-engine）         | 本机环回受限、不宜直连外网 | Python 实现  | ⚪ 备选（复杂）           |
| D. 借助第三方在线服务                            | 依赖第三方稳定性/费用      | 第三方       | ❌ 不采用（成本且不可控） |

**推荐：B**。理由：网络层用现成 Rust `reqwest`（已论证可靠），解密放在 Rust（大整数/字节流计算，性能好、无 CORS、会话凭据不出本机），解出的可播放 m4a 通过 Tauri 事件/API 回传前端，前端仅负责展示与“保存为文件”（复用 `@tauri-apps/api`）。

> 备选 B'：解密也可放在已被项目捆绑的 Python 本地引擎中（同域 `127.0.0.1` 服务），用 Python 大整数运算实现。二者取其一，工程上保持一致、避免双栈重复实现。

### 2.6 转码承载选型（最终：ffmpeg）

解密产物是 Opus-in-MP4 的 fMP4，需转码为 320kbps mp3 才能作为试听交付物。转码承载有两个方向，对比如下：

| 方向                                                  | 优点                                                                          | 缺点                                                                                             | 结论          |
| ----------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------- |
| **Rust 侧自编码**（如 `symphonia` + `lame`/`rubato`） | 无外部依赖、可打包分发                                                        | 需引入多个 crate 并自行打通"解码 Opus → 重采样 → LAME 编码"链路，编码质量/特性需自测，开发成本高 | ⚪ 复杂，不选 |
| **复用系统 / 本地 ffmpeg**（推荐）                    | 一条命令完成"解码 + 规范化为 320kbps mp3"，质量稳定、成熟、省开发量；兼容性好 | 需在本机安装 ffmpeg 二进制，或通过 `imageio-ffmpeg`/捆绑引擎管理 ffmpeg 依赖                     | ✅ **采用**   |

**已确认：转码承载走 ffmpeg。** 工程落地方式：

- 优先复用本机已安装的 `ffmpeg`（实测系统已具备）；在 Tauri 侧通过 `tokio::process::Command` 调用 `ffmpeg -i <明文fmp4> -codec:a libmp3lame -b:a 320k -f mp3 <out.mp3>`。
- 若需打包分发保证环境一致，可选 `imageio-ffmpeg` 下载并托管 ffmpeg 二进制，进程启动前探测 PATH；未命中时走托管二进制，二者接口一致。
- 目标参数：`libmp3lame`、`-b:a 320k`，输出采样率/声道与源一致（Opus 源通常 44.1kHz 立体声）。

## 3. 技术方案设计

### 3.1 总体架构（Tauri 端）

```
浏览器(前端)                Tauri Rust                         Suno
   │ 输入 /s/<token>           │                                │
   │ ───────────► 解析ID/uuid  │  reqwest GET 元数据 ────────► │
   │                          │  stream_audio_url ◄────────── │
   │                          │  reqwest GET 加密流 ────────►│
   │                          │  加密 m4a ◄────────────────── │
   │                          │  本地解密算法                 │
   │                          │  ── 产出明文 fMP4 ─────────── │
   │                          │  ffmpeg 转码 320kbps mp3      │
   │  ◄── 320kbps mp3(事件/API)│  ── 产出试听 mp3 ──────────── │
   │  保存为文件(试听缓存)                                    │
```

### 3.2 模块划分

| 模块         | 位置                                       | 职责                                                                                                                     |
| ------------ | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 链接解析器   | `src/services/suno-link/`（前端）          | 校验/归一化分享链接，提取 token 或 uuid                                                                                  |
| 元数据客户端 | Rust `src-tauri/src/suno_probe.rs`（新增） | reqwest 请求元数据（标题/封面/时长），落缓 `{id, title, cover, duration}`；播放流地址由 `content_id` 构造（不依赖 feed） |
| 播放流下载器 | Rust                                       | 按 `content_id` 从 CloudFront 直取加密 m4a 字节（分块下载），密钥经 `/api/mango/rights` 获取                             |
| 解密器       | Rust（或 Python 引擎备选）                 | 复刻自用户已验证的 Suno 前端算法，解出明文 fMP4                                                                          |
| 转码器       | Rust 调用 ffmpeg                           | `ffmpeg -i fMP4 -codec:a libmp3lame -b:a 320k` → 320kbps mp3（见 §2.6）                                                  |
| 前端交互     | `src/pages/` 复用现有 Pro 表单/步骤        | 输入链接 → 进度 → 持 320kbps mp3 → 保存文件                                                                              |

### 3.3 核心流程（伪代码级）

```
async fn download_trial_audio(link: String) -> Result<Vec<u8>> {
    let uuid = resolve_song_id(link).await?;                 // 短链→uuid（share/code），或直取
    let meta = fetch_metadata(uuid).await?;                  // 标题/封面/时长（reqwest）
    let rights = get_rights(uuid).await?;                    // POST /api/mango/rights → {key,iv,glt}
    let encrypted = fetch_stream_by_id(uuid, &rights).await?; // 按 content_id 从 CloudFront 直取加密 m4a
    let fmp4 = suno_decrypt(encrypted, rights)?;             // 本机算法（AES-GCM 解包 + AES-CTR）
    let mp3 = ffmpeg_transcode(fmp4, 320_000)?;             // ffmpeg → 320kbps mp3（见 §2.6）
    Ok(mp3)
}
```

## 5. 风险与合规

### 5.1 合规 / 账号风险（必须向用户明示）

- 抓取播放流并本地解密，实质是**绕过 Suno 的 DRM 技术保护**。社区类似工具普遍标注“违反 Suno ToS，可能导致账号被风控/封禁”，并存在《数字千年版权法》§1201 类型的技术规避责任探讨。
- 本项目**只用于少量、客户试听选型**这一有限场景，不应泛化为一键批量抓取工具。
- 建议在产品与文档中明确“试听用途”边界，避免用于再分发或商业转售成品。

### 5.2 技术风险

| 风险                                                        | 影响             | 缓解                                                                                        |
| ----------------------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------- |
| Suno 前端升级改变解密算法/密钥                              | 功能失效         | 抽出单一 `suno_decrypt`，升级时快速回归；关注 Suno 更新                                     |
| 反爬增加登录/风控（`browser-token`、`device-id`、设备绑定） | 匿名抓取被拦截   | 控制在本地生成的 `browser-token`/`device-id` 范围内；不注入用户会话凭据；失败时给出明确错误 |
| 私有/未公开曲目匿名不可达                                   | 部分链接无法解析 | 需求限定为“公开分享链接”，私有曲目给出提示                                                  |
| 本机缺少 ffmpeg 二进制                                      | 转码阶段失败     | 启动前探测 PATH；未命中用 `imageio-ffmpeg` 下载托管二进制兜底（见 §2.6）                    |
| m4a 分段/容器差异                                           | 解密后容器不标准 | PoC 阶段确认解码后是否需 repack（如重写 ftyp/moov）                                         |
| ffmpeg 参数随版本变化                                       | 输出行为漂移     | 锁定命令参数（`-codec:a libmp3lame -b:a 320k`），升级后回归                                 |

### 5.3 数据与安全

- 关键点：**解密逻辑与任何会话凭据均停留在用户本机**（Tauri Rust 进程或本地引擎），不上传任何云端；符合本项目“音频不出本机”既有约定。
- 下载的试听文件仅落本地并可选择导出，前端不留大二进制常驻内存。
